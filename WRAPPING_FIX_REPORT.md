# Отчет: Исправление обработки длинных имен в резюме

## 📋 Сводка выполненной работы

Успешно реализована обработка длинных фамилий/имен во всех 4 шаблонах резюме (Classic, Modern, Professional, Creative) с автоматическим переносом текста на следующую строку.

## 🔧 Проблемы, которые были решены

### 1. **Ошибка валидации UTF-8** ❌→✅
- **Проблема**: Валидация использовала `len(r.FullName)` который считает **байты**, а не символы
- Кириллические символы занимают 2-3 байта в UTF-8, поэтому имя из 76 символов = ~200+ байтов
- Это вызывало отклонение имен, которые были в пределах лимита 100 символов
- **Решение**: Заменил на `utf8.RuneCountInString(r.FullName)` для корректного подсчета символов

**Файл**: [internal/models/resume.go](internal/models/resume.go#L233)
```go
// Было:
if len(r.FullName) == 0 || len(r.FullName) > 100 { ... }

// Стало:
if utf8.RuneCountInString(r.FullName) == 0 || utf8.RuneCountInString(r.FullName) > 100 { ... }
```

### 2. **Отсутствие переноса текста в PDF** ❌→✅
- **Проблема**: Длинные имена либо накладывались на фото, либо выходили за границы страницы
- **Причина**: Использовался `pdf.Cell()` который не переносит текст на новую строку
- **Решение**: Заменил все `Cell()` на `MultiCell()` во всех шаблонах для автоматического переноса

**Файл**: [internal/pdf/pdf.go](internal/pdf/pdf.go)

Все шаблоны теперь используют MultiCell с правильными параметрами ширины:
- **Classic**: Динамическая ширина 120-170мм в зависимости от наличия фото
- **Modern**: Фиксированная ширина 150мм
- **Professional**: Фиксированная ширина 130мм  
- **Creative**: Динамическая ширина 125мм (с фото) / 180мм (без)
